## 프로젝트 소개

동구라미는 수원대학교 중앙동아리의 모집 과정을 한곳에 모은 서비스입니다. 학생은 동아리를 찾아보고 지원합니다. 동아리 회장은 지원자를 합격·불합격 처리해 결과를 알립니다. 동아리연합회는 동아리 등록과 공지를 관리합니다.

2024년 6월에 모바일 앱으로 시작한 서비스이고, 2025년 9월 웹으로 전환할 때 제가 2기 백엔드 팀장으로 합류했습니다. 세 종류의 사용자를 Spring Boot 서버 하나가 처리합니다.

## 주요 기능

서비스의 기능 대부분은 1기 팀이 만들었습니다. <span class="mine">담당</span> 표시는 제가 만들거나 고친 기능입니다.

<div class="feature-grid">

- **동아리 찾기** 분과별 전체 목록, 모집 중인 동아리만 보기, 관심 카테고리로 찾기를 제공합니다.
- **동아리 상세** 소개 글과 모집 글, 활동 사진, 동아리방 위치를 보여 줍니다.
- **가입과 로그인** 학교 포털 메일로 인증해 가입합니다. 로그인과 메일 발송은 5분에 5회로 제한합니다.
- **지원** <span class="mine">담당</span> 지원할 수 있는지 확인하고 지원 사실을 기록합니다. 같은 동아리에 지원서가 두 번 들어가지 않도록 중복 제출을 막았습니다.
- **합격·불합격 처리** 회장이 지원자를 한꺼번에 처리하면 지원자에게 푸시 알림이 갑니다. 합격자는 부원 명단에 자동으로 추가됩니다.
- **부원 관리** 명단 조회와 엑셀 내보내기, 엑셀로 기존 부원 등록, 가입 요청 승인을 제공합니다.
- **동아리연합회 관리** 동아리 등록(회장 계정 발급)과 삭제, 카테고리, 공지, 동아리방 층별 도면을 관리합니다.
- **동아리의 밤 현장 인증** <span class="mine">담당</span> 행사장에서 공개한 4자리 코드를 입력해 참석을 인증합니다. 한 사람당 한 번만 인증할 수 있습니다.
- **API 문서** <span class="mine">담당</span> Swagger UI와 ReDoc으로 API 문서를 제공합니다.

## 담당 역할

- **직접 구현** 동아리의 밤 현장 인증 API, 지원서 중복 제출 방지, 웹 전환을 위한 CORS·쿠키 설정, 배포 자가복구 단계, API 문서(Swagger · ReDoc).
- **기존 팀원 작업** JWT와 Redis 리프레시 토큰, 레이트리밋, 엑셀 일괄 등록, 블루/그린 배포 파이프라인의 원형. 저는 기존 구조를 파악한 뒤 그 위에 기능을 추가했습니다.

## 사례 1 · 동아리의 밤 현장 인증

- **배경** 오프라인 행사(2025-10-30)에서 참석자가 본인 계정으로 인증하는 기능이 필요했습니다. 기존의 카카오톡방 확인 방식은 휴대폰을 빌려주는 대리 인증을 막을 수 없었습니다.
- **저장소 선택** 처음에는 Redis 키로 인증 여부를 저장했습니다. 자동 코드 리뷰에서 만료 시간이 없다는 지적을 받고 검토해 보니, 이 기록은 만료되면 안 되고 나중에 누가 인증했는지 조회해야 하는 이력 데이터였습니다. 그래서 저장소를 MySQL 테이블로 변경했습니다.
- **규칙** 1인 1회는 DB 유니크 제약으로 보장합니다. 인증 코드 무작위 대입을 막기 위해 사용자당 5분에 5회로 제한했습니다. 소속 동아리는 클라이언트가 보낸 값 대신 서버가 조회하도록 했고, 이 부분은 팀원과 함께 마무리했습니다.
- **결과** 행사 당일 16\~20시에 210건을 처리했고, 가장 많았던 1시간에는 81건이었습니다.
- **이후 보강** 동시 요청이 유니크 제약에 걸리면 "이미 인증됨"으로 응답하게 하고, 인증 코드 기본값을 제거해 설정되지 않은 경우 모든 요청을 거절하도록 했습니다. 단위 테스트 8개를 추가했습니다.

## 사례 2 · 지원서 중복 제출

- **문제** 지원서 제출이 "조회해서 없으면 저장" 구조라, 동시 요청이나 더블클릭이 오면 둘 다 통과할 수 있었습니다. 또한 처리가 끝난 과거 지원까지 조회 대상에 포함돼서, 재모집 때 다시 지원할 수 없었습니다.
- **해결** 조회 대상을 처리 전 지원서로 좁혔습니다. 동시 요청은 DB 유니크 제약으로 최종 차단하고, 제약 위반 예외를 "이미 지원함" 응답으로 바꿨습니다.
- **부분 유니크** MySQL에는 "처리 전인 행만 유니크"라는 제약이 없습니다. 운영 DB는 처리 전일 때만 값이 있는 생성 컬럼을 유니크 키에 넣어 같은 효과를 냅니다. 엔티티 선언을 이 방식에 맞춰 로컬과 운영의 스키마 차이를 없앴습니다.
- **결과** Testcontainers MySQL에서 같은 사용자가 동시에 20건을 제출하면 1건만 성공하고 19건은 "이미 지원함" 응답을 받습니다. 3회 연속 실행해 모두 통과했습니다.

## 기타 작업

- **모바일 앱에서 웹으로 전환** 허용 origin을 여러 개 받도록 바꾸고, 하드코딩돼 있던 쿠키 SameSite를 환경별 설정으로 분리했습니다. 본문을 받던 GET API는 브라우저에서 호출할 수 없어 POST로 바꿨습니다.
- **배포 자가복구** 배포 중 서비스가 시작되지 않는 장애를 겪은 뒤, 헬스체크가 실패하면 프로세스를 정리하고 재시작해 다시 검사하는 단계를 워크플로에 추가했습니다. 복구 중에는 서비스가 중단됩니다.


## 회고

합류 당시 실행되는 테스트가 없었고 CI는 빌드만 확인했습니다. 당시에는 기능 구현을 우선하느라 테스트 없이 머지했고, 리뷰도 충분히 하지 못했습니다. 이후 제가 구현한 기능부터 테스트 11개를 추가했습니다.
