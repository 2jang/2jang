## 프로젝트 소개

수원대학교 지능형SW융합대학을 소개하는 웹사이트입니다. 학부 3개와 학과 5개를 소개하고, 재학생과 예비 신입생이 쓸 수 있는 기능 네 가지(졸업요건 확인, 캠퍼스 길찾기, 학부 대항 실시간 클릭 게임, AI 챗봇)를 함께 제공합니다.

1주일 동안 진행된 교내 해커톤에서 만든 팀 프로젝트이고 대상을 받았습니다. 저는 React 프론트엔드를 맡았습니다. 해커톤이 끝난 뒤에는 혼자 개인 도메인에 배포하고 수정해 왔습니다.

## 주요 기능

<span class="mine">담당</span> 표시는 화면을 제가 만든 기능입니다. 서버(Spring Boot)는 팀원 작업입니다.

<div class="feature-grid">

- **학부·학과 소개** 학부 3개와 학과 5개의 소개, 주요 교과목, 교수진을 보여 줍니다.
- **졸업요건 확인** <span class="mine">담당</span> 학과를 고르고 요건을 체크하면 충족 여부와 충족한 비율을 보여 줍니다.
- **캠퍼스 길찾기** <span class="mine">담당</span> 캠퍼스 지도에서 출발 건물과 도착 건물을 누르면 경로와 예상 도보 시간, 직선거리를 보여 줍니다.
- **학부 대항 클릭 게임** <span class="mine">담당</span> 버튼을 누르면 접속한 모든 사람의 화면에 점수가 바로 반영됩니다. 순위에 따라 카드 순서가 바뀌고, 피버 게이지가 차면 10초 동안 클릭이 2배로 반영됩니다.
- **AI 챗봇** 모든 페이지에서 챗봇 창을 열어 질문합니다.
- **모바일 화면** 휴대폰 폭에 맞춰 글자 크기와 배치를 조정합니다.

## 담당 역할

- **화면** 졸업요건 확인, 캠퍼스 길찾기, 클릭 게임 화면을 만들었고, 학과 페이지 5개의 대부분을 작성했습니다.
- **챗봇** 화면의 서버 연결과 재시도를 맡았고, 해커톤이 끝난 뒤 서버의 LLM 연결을 OpenRouter로 바꿨습니다.
- **배포** 해커톤이 끝난 뒤 개인 서버 배포, 도메인 이전, 번들 최적화를 했습니다.
- **팀원 작업** 메인과 학부 페이지 3개, 메뉴, 교수 데이터, 모바일 대응, 서버의 길찾기 시간 표와 클릭 집계·방송.

## 구조

| 구성 | 내용 |
| --- | --- |
| 화면 | React SPA |
| 서버 | Spring Boot(별도 저장소). 길찾기 도보 시간 조회(REST), 클릭 점수 집계와 실시간 방송(STOMP WebSocket), 챗봇 질문을 LLM에 전달 |
| 실시간 연결 | 처음 점수는 REST로 받고 이후 변화는 WebSocket으로 받습니다. 연결이 끊기면 5초 간격으로 다시 연결합니다. |

## 사례 1 · 길찾기에 표시되던 부정확한 소요 시간

- **문제** 도보 소요 시간이 실제와 맞지 않았습니다. 직선거리도 근거 없는 상수(`픽셀 거리 × 2.5`)로 계산하고 있었습니다.
- **원인** 서버 응답 대신 화면에서 "직선거리 ÷ 분당 67m"로 시간을 계산했고, 서버 요청이 실패해도 같은 추정값을 정상 값처럼 보여 줬습니다.
- **해결** 소요 시간은 서버 응답만 쓰고, 실패하면 "정보 없음"과 오류 알림을 표시하도록 바꿨습니다. 직선거리는 실제 거리를 아는 두 건물(840m)로 지도 축척을 구해 계산합니다.
- **결과** 서버 요청이 실패했을 때 잘못된 값이 표시되지 않습니다. 직선거리의 정확도는 따로 측정하지 않았습니다.

## 사례 2 · 배포 환경이 바뀔 때마다 동작하지 않던 서버 주소

- **문제** 해커톤 중에는 화면이 학교 서버 주소를 직접 호출했습니다. 이후 개인 서버, 로컬, 새 도메인으로 환경이 바뀔 때마다 길찾기·클릭 게임·챗봇이 동작하지 않았습니다.
- **원인** 서버 주소를 소스 코드에 문자열로 적어 두었고, 그 주소가 파일 3개에 흩어져 있었습니다.
- **해결** 접속한 주소에 따라 REST·WebSocket·챗봇 주소를 고르는 함수를 만들고, 프로토콜에 따라 `ws`와 `wss`를 고르게 했습니다.
- **한계** 도메인이 바뀌면 여전히 소스를 고쳐야 합니다.
