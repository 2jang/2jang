## 프로젝트 소개

세탁실에 가지 않고도 빈 세탁기가 있는지, 내 빨래가 언제 끝나는지 알 수 있게 해 주는 기숙사 세탁실 서비스입니다. 세탁기에 붙인 진동 센서가 세탁·탈수·완료 상태를 서버로 보내면, 학생은 웹(PWA)에서 실시간 현황을 보고 세탁이 끝났을 때 휴대폰으로 알림을 받습니다.

기숙사 세탁실 1곳(기기 4대)에서 약 20명을 대상으로 시범 운영했습니다.

## 주요 기능

<span class="mine">담당</span> 표시는 제가 주로 만든 기능입니다. 센서 펌웨어와 웹 화면 대부분, 서버의 상태 전이 처리와 혼잡도 집계는 팀원 작업입니다.

<div class="feature-grid">

- **실시간 세탁실 현황** <span class="mine">담당</span> 세탁기별 상태(세탁 중·탈수 중·건조 중·완료)와 남은 시간을 새로고침 없이 보여 줍니다. 서버가 상태 변화를 WebSocket으로 보냅니다.
- **세탁 완료 알림** <span class="mine">담당</span> 세탁을 시작할 때나 돌아가는 세탁기에 알림을 걸어 두면, 끝났을 때 휴대폰으로 푸시를 보냅니다.
- **빈자리 알림** 모든 세탁기가 사용 중일 때 켜 두면 하나라도 끝났을 때 알려 줍니다.
- **혼잡도 분석** 요일과 시간대별 평균 사용 대수를 차트로 보여 줍니다.
- **AI 세탁 시간 추천** <span class="mine">담당</span> 혼잡도와 날씨를 바탕으로 한산한 시간을 한 줄로 추천합니다.
- **PWA 설치 안내** <span class="mine">담당</span> iOS, Android, PC에 맞는 설치 방법을 안내합니다.

</div>

## 담당 역할

- **백엔드** 서버 개발을 주도했습니다(서버 커밋의 84%). 실시간 전송(WebSocket), 푸시 알림(FCM), AI 추천과 날씨 캐시를 포함해 서버 대부분을 만들었습니다.
- **웹** 웹 푸시와 서비스 워커, iOS PWA 대응, 플랫폼별 설치 안내, 배포(GitHub Pages)를 맡았습니다.
- **팀원 작업** 센서 펌웨어, 서버의 상태 전이 처리·혼잡도 집계·진동 기준점 계산, 웹 화면 디자인과 화면 로직 대부분.

1. 센서가 세탁기 상태를 판정해 서버로 보냅니다. 기기마다 발급한 JWT로 인증합니다.
2. 서버가 상태를 MySQL에 저장하고 시작·탈수·완료를 판단합니다.
3. 서버가 WebSocket으로 웹 화면을 갱신하고, 완료되면 FCM으로 푸시를 보냅니다.
4. 날씨와 AI 추천 문구는 센서 이벤트가 들어올 때 백그라운드에서 갱신해 두고, 사용자 요청에는 캐시로 응답합니다.

## 사례 · 병렬 조회가 DB 커넥션 풀을 고갈시킨 문제

- **문제** AI 추천 API가 느려서 조회 6개를 `asyncio.gather`로 병렬화했습니다. 적용 16분 뒤 커넥션 풀 오류가 발생했습니다.
- **원인** 풀 크기가 5였고, 이 드라이버의 풀은 남은 연결이 없으면 기다리지 않고 즉시 실패합니다. 요청 한 건이 풀 전체를 점유해서 동시 요청 2건이면 바로 실패했습니다.
- **해결** 먼저 순차 실행으로 되돌려 안정성을 확보했습니다. 그다음 느린 LLM과 기상청 API 호출을 사용자 요청 경로에서 분리했습니다. 센서 이벤트가 들어오면 백그라운드에서 캐시를 갱신하고, 사용자 요청은 DB 캐시만 읽습니다.
- **결과** 추천 API는 쿼리 1개로 응답합니다. 응답 시간: <Todo>측정 필요</Todo>

## 클라이언트 연동

- 웹 푸시가 한 건도 도달하지 않던 문제를 서버의 FCM 메시지 형식과 웹의 서비스 워커를 함께 수정해 해결했습니다.
- iOS는 홈 화면에 설치한 PWA(16.4 이상)에서만 웹 푸시를 지원하므로, 설치 안내와 토큰 발급 과정을 이에 맞게 구현했습니다.
- 웹은 GitHub Pages와 커스텀 도메인으로 배포했습니다. 화면 대부분은 팀원 작업입니다.
