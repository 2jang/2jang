## 프로젝트 소개

반려견 보호자가 카카오톡에서 쓰는 챗봇과, 반려견의 성격을 알아보는 웹 검사입니다. 카카오톡 채널에 자기 MBTI를 보내면 성향이 맞는 견종을 추천받습니다. 웹 페이지에서 강아지에 관한 12문항에 답하면 반려견의 성격 유형(DBTI)이 나오고, 챗봇에서 그 결과를 요청하면 유형의 특징과 양육 방법을 카드로 받습니다.

챗봇과 웹 검사는 같은 Flask 서버에 연결됩니다. 카카오톡에서 보낸 말은 카카오 i 오픈빌더(카카오의 챗봇 제작 도구)가 이 서버로 전달하고, 서버가 답을 만들어 돌려줍니다. 이렇게 호출되는 서버를 스킬 서버라고 합니다.

## 주요 기능

<span class="mine">담당</span> 표시는 제가 주로 만든 기능입니다. 검사 화면의 디자인과 애니메이션은 팀원이 만들었고, 저는 그 화면을 서버 페이지로 옮겨 수정했습니다.

<div class="feature-grid">

- **MBTI 견종 추천** <span class="mine">담당</span> 카카오톡에 MBTI 네 글자를 보내면 유형 설명과 어울리는 견종 카드로 답합니다. 목록에 없는 값이면 올바른 유형을 입력하라고 안내합니다.
- **웹 성향 검사** 산책, 놀이, 생활 상황 12문항에서 둘 중 하나를 고르면 반려견의 성격 유형이 나옵니다.
- **진행 애니메이션** 문항을 따라 내려갈수록 화면 위쪽의 사람과 강아지가 가까워지고, 마지막 문항에서 만납니다.
- **결과 전송** <span class="mine">담당</span> 검사가 끝나면 결과를 서버로 보냅니다. 전송이 실패해도 결과 창은 보여 줍니다.
- **결과와 양육 방법 카드** <span class="mine">담당</span> 검사 뒤 챗봇에서 결과를 요청하면 유형 이름과 특징, 양육 방법을 차례로 답합니다. 검사 전이면 먼저 검사하라고 안내합니다.
- **데이터 적재** <span class="mine">담당</span> DBTI 유형, MBTI 설명, MBTI별 추천 견종을 CSV 세 개로 두고 서버가 시작할 때 읽습니다. MBTI 설명은 팀원이 만든 크롤러로 모았습니다.

</div>

## 담당 역할

- **서버** Flask 서버를 만들었습니다. 카카오 i 오픈빌더가 호출하는 스킬 API 두 개와 웹 검사 결과를 받는 API, 카카오톡 카드 응답 형식을 맡았습니다.
- **연동 구조** 웹에서 검사하면 서버가 결과를 받아 두고, 챗봇에서 요청하면 카드로 답하는 흐름을 정했습니다.
- **웹 검사** 팀원이 만든 검사 화면을 서버가 제공하는 페이지로 옮겨 통합하고, 문항 채점과 유형 변환, 결과 전송을 추가했습니다.
- **데이터** DBTI 유형과 추천 견종 데이터를 CSV로 정리했습니다. 유형 설명은 포동(fordong.co.kr)의 자료를 참고했습니다.
- **팀원 작업** 검사 화면의 디자인과 스크롤 애니메이션 원형, MBTI 설명을 모으는 크롤러 원형.

- **챗봇** 카카오톡에서 보낸 말은 카카오 i 오픈빌더를 거쳐 Flask 서버의 스킬 API로 들어옵니다. 서버는 카카오가 정한 응답 형식(말풍선과 카드)으로 답합니다.
- **웹 검사** 같은 서버가 검사 페이지를 제공합니다. 검사가 끝나면 브라우저가 결과를 서버로 보내고, 서버는 이 결과를 메모리에 둡니다.
- **데이터** DB는 쓰지 않습니다. CSV 세 개를 서버가 시작할 때 읽어 메모리에 보관하고, 요청마다 키로 찾습니다.

## 한계

- **결과 저장** 서버는 사용자를 구분하지 않고 마지막 검사 결과 하나만 메모리에 둡니다. 두 사람이 동시에 쓰면 결과가 섞이고, 서버를 다시 시작하면 사라집니다. 처음에는 MySQL에 저장했다가, 개발 중에 메모리에 두는 방식으로 바꿨습니다.
- **실행 환경** Flask 개발 서버로 실행합니다. Docker나 배포 스크립트 같은 배포 구성은 만들지 않았습니다.
- **현재 코드** 2025년에 파일을 정리하면서 지운 음성 인식 모듈을 서버 코드가 아직 불러오고 있어, 저장소의 최신 코드는 그대로는 실행되지 않습니다. 이 페이지의 화면은 그 모듈을 빈 모듈로 대신해 실행하고 찍었습니다.
